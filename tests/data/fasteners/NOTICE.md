# FreeCAD Fasteners workbench reference data

Reference sources and golden values for the Standard Parts fasteners plugin. Everything here comes from the
FreeCAD Fasteners workbench:

- Repository: https://github.com/shaise/FreeCAD_FastenersWB
- Commit: `375a73d9706a30072c132fb061e7636e8ed99f82` (default branch head on 2026-11-13)
- Licence: LGPL-2.1-or-later (`upstream/LICENSE`, copied from the repository). FreeShape's own
  GPL-3.0-or-later licence does not apply to these files.

Copyright holders are the workbench authors named in each file header (among them Ulrich Brammer, Shai Seger and
Andrey Bekhterev). The files are data for tests and porting reference, not linked code.

## Files

| File here | Source path in the workbench repository | Extraction |
|---|---|---|
| `upstream/screw_maker.py`, `FastenerBase.py`, `ScrewMaker.py`, `FSutils.py`, `LICENSE` | same name at repository root | unmodified copy |
| `upstream/FsFunctions/FSmake{HexHeadBolt,CylinderHeadScrew,HexNut,Washer,SelfTappingScrew}.py` | `FsFunctions/` | unmodified copy |
| `upstream/FsData/*.csv` | `FsData/` | unmodified copy |
| `freecad_goldens.json` | none | generated by `scripts/fasteners/export_freecad_goldens.py` |

The CSV tables are the ones the vendored sources read for ISO 4014, 4017, 4762, 4032, 7089 and 7049-C/F/R:
`iso4014head`, `iso4017head`, `iso4762def`, `iso4032def`, `iso7089def`, `iso7049head` (its labels are
`ISO7049-C/F/Rdef`, `-length`, `-range`), `iso1478def` (tapping-screw thread), `DiaList`, `iso4757def` (cross
recess) and `iso68def` (`ISO68-1def`, metric thread depths). A table name is the quoted label line inside a CSV;
a CSV without one takes its file name, which is the case for `iso1478def`, `DiaList` and `iso4757def`.
ISO 4032 and ISO 7089 have no length or range tables.

## Goldens

`freecad_goldens.json` holds volume, bounding box and the dimension-table row for each part, built by the
workbench itself with threads off under FreeCAD 1.0.2 (build 39319), run headless with `FreeCADCmd`. The header
repeats the commit and version. The script's docstring gives the regeneration command.
